What is SLAM?

Simultaneous Localization and Mapping (SLAM) solves a chicken-and-egg problem: to build a map you need to know where you are, but to know where you are you need a map. Modern SLAM algorithms solve both simultaneously.

The SLAM Pipeline

  • Sensor Input: LiDAR, stereo camera, RGB-D, or IMU
  • Feature Extraction: Identifying landmarks in sensor data
  • Data Association: Matching current observations to known landmarks
  • State Estimation: Updating robot pose and map (EKF, particle filter, factor graph)
  • Loop Closure: Recognizing previously visited places to correct drift

LiDAR SLAM with RTAB-Map

ros2 launch rtabmap_ros rtabmap.launch.py \
  --ros-args \
  -p use_sim_time:=false \
  -p subscribe_scan:=true \
  -p frame_id:=base_link \
  -p odom_frame_id:=odom \
  -p queue_size:=10

Visual SLAM with ORB-SLAM3 + ROS2

ros2 run orbslam3_ros stereo \
  --ros-args \
  -p vocabulary_path:=/path/to/ORBvoc.txt \
  -p settings_path:=/path/to/stereo_params.yaml

Integrating SLAM with Nav2

Once your SLAM system publishes a /map topic and maintains the map→odom transform, Nav2 picks it up automatically:

# Verify transforms are being published
ros2 run tf2_tools view_frames

# Check map is available
ros2 topic echo /map --once

Common Pitfalls

  • TF drift: Always ensure your odom source is reliable before adding SLAM
  • Loop closure frequency: Too aggressive causes jitter; tune the threshold carefully
  • Memory usage: RTAB-Map can grow large; configure max memory and working memory
  • Time sync: Ensure all sensor timestamps are synchronized (use chrony or hardware sync)
