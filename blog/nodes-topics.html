The ROS2 Communication Model

Everything in ROS2 revolves around nodes — processes that perform computation — and several communication patterns they use to talk to each other. Choosing the right pattern is critical for system performance and reliability.

Nodes

A node is the smallest computational unit in ROS2. Each node typically handles one responsibility: reading a sensor, computing odometry, or planning a path.

import rclpy
from rclpy.node import Node

class MyRobot(Node):
    def __init__(self):
        super().__init__('my_robot_node')
        self.get_logger().info('Robot node started!')

def main():
    rclpy.init()
    node = MyRobot()
    rclpy.spin(node)
    rclpy.shutdown()

Topics: Publish / Subscribe

Topics are the backbone of sensor data and state streaming. They're asynchronous and support many-to-many communication.

# Publisher
self.pub = self.create_publisher(LaserScan, '/scan', 10)

# Subscriber
self.sub = self.create_subscription(
    LaserScan, '/scan', self.scan_callback, 10)

Use topics for: sensor data (LiDAR, IMU, camera), velocity commands, robot state, and any continuous stream.

Services: Request / Response

Services are synchronous — the client blocks until the server responds. Use for discrete, short-duration tasks.

# Service call
from nav_msgs.srv import GetMap
client = self.create_client(GetMap, '/map_server/map')
req = GetMap.Request()
future = client.call_async(req)

Use services for: getting map data, triggering resets, querying robot configuration.

Actions: Long-running Tasks

Actions are ideal for navigation goals, arm movements, or any task that takes time and needs progress feedback.

from nav2_msgs.action import NavigateToPose
from rclpy.action import ActionClient

self._action_client = ActionClient(
    self, NavigateToPose, 'navigate_to_pose')

Use actions for: go-to-pose goals, manipulation sequences, docking procedures.

Choosing the Right Pattern

  • Continuous stream → Topic (pub/sub)
  • Quick request/response → Service
  • Long task with feedback → Action
  • Shared global state → Parameter server
